回答的问题：字多大、放哪里、用什么样子；图装在什么框里；同一个设计换画幅时怎么办。

## 1. 先分清：要被读的字，和只要被看到的字

这一份文件里的多数判断，都从这个区分出发。

- **要被读的**：歌词、片名、署名、观众必须知道的信息。它需要足够的字号、足够的停留时间、稳定的位置、清晰的边缘。
- **只要被看到的**：当图形用的大字、当纹理用的小字、当标注用的标签。它可以被拉伸、镜像、切断、盖住、一闪而过。

素材里两类字的待遇差别很大（见下面各节）。动手之前把每一处文字归到其中一类；归不进去的，多半可以删。

**大小和时间一起定**

- 要被读的字，除了字号，还要给时间。逐帧量到的完整停留时间：占满画面的一个大词 5—10 帧；两三个词的署名约 10 帧；一个要读的词或一句歌词 22 帧到 40 帧以上；一整版带几十个小标签的拼贴只有 2—9 帧。完整的表和出处在 [motion-and-transitions.md](motion-and-transitions.md) 第 9 节。
- V05 0:54.4—0:55.3 把两类字叠在同一个画面里：占满画面的大词每 5 帧换一个；压在上面的括号编号和三行释义小字不换。释义的标题里出现的词，至少有两个就是轮流出现的大词——大词是词条，小字是释义。
- 解读：同一组信息被分给了两个尺度和两种时间。大的那一层 5 帧就认得出来；小的那一层一秒钟读不完，是给暂停的人看的。这和第 4 节「同一个标题写两遍」是同一个思路，多了时间这一维。
- 代价：小的那一层在播放时等于纹理。真要观众读到释义，得给它单独的时间，或者另外发静帧（见 [stills-and-motion.md](stills-and-motion.md) 第 4、6 节）。

## 2. 字号：大字很少，小字很多，中间很稀

**看到的**

对 17 帧版式做了粗略测量（把文字的连通域串成行，取字高，换算成画面高度的百分比）：

| 画面 | 最大的字 | 中间（约 3%—9%） | 小字（不超过 2.7%） |
|---|---|---|---|
| V02 0:33 章节卡 | 17.9% | 1 行（4.9%，是被演示图形的标签） | 5 行，最小 1.2% |
| V05 0:22 标题 | 10%，3 处 | 3 行（5.2%，方括号小标签） | 20 行，0.8%—2.2% |
| V08 1:36 纸面段 | 35% | 2 行（字块 9.9%、假名 6.1%） | 6 行，0.6%—1.5% |
| V08 1:53 纸面段 | 19.5%、17.2% | 3 行（5%—6.6%） | 7 行 |
| V23 0:08 歌词（字体排印另有署名） | 13.9% | 0 行 | 9 行，0.5%—2.7% |
| V34 0:34 歌词卡（平面设计另有署名） | 45.5% | 0 行 | 极小的标签没检测到 |
| V11 0:08、V20 0:06 | 约 19% | 0 行 | 0—1 行 |
| V00 0:22 标题卡 | 9.1%、7.6%、6.5% | 3 行（2.6%—3.7%） | 18 行，0.8%—1.8% |
| V03 0:21 章节卡 | 约 7% | 3 行（2.8%—3.5%） | 3 行 |
| V16 0:04 | 约 11%—12%，3 处 | 22 行 | 31 行 |
| V13 2:32 副歌（字体排印另有署名） | 5.7% | 歌词的词都在 4.2%—5.7% | 谱线上的小件 |
| V17 0:28、V26 0:34 | 2.4%、2.1%（歌词和字幕） | — | — |

- 图形类作品里，大字只有 1—3 处，字高占画面高度的 10%—45%。多数文字不超过 2.7%，1080p 下约 29 像素。3%—9% 这一段不是空的，而是很稀，通常 0—3 个元素。
- 最大的字与数量最多的小字相差 5—30 倍。
- 三种例外：
  - 歌词需要被读的片子，歌词就在中间这一段或稍小（V13、V17、V26）。
  - V16 的标签贴在带透视的地面上，各种大小连续分布。
  - V03 的章节卡四档之间各差约 2 倍，是一套均匀的阶梯。
- 最大的不一定是第一位。三个例子：
  - V05 0:55（图片 B06 是其中一帧）：占满画面的字母最暗、边缘是虚的，退成了背景；最细的白线最亮、最清楚。
  - B01：最重的是满屏的黑白条带，主体是一个很细的蓝色圆和几笔蓝色弧线。全图只有主体是蓝的。
  - B05（V05 0:47）：描边的大字母和底几乎同色，只靠黑色细描边显出来；一眼先看到的是占画面 3.5% 的蓝色块。

**可能的原因**

- 大字在当图形用：一眼看到的是形状，数量少，所以谁是第一位很清楚。
- 小字在当纹理或系统信息用：它给出密度和「被精确记录过」的感觉，愿意读的人可以读，不读也不影响。
- 中间那一档是正文的大小，它要求观众一行一行地读。镜头只有零点几秒到一两秒时，没有这个时间。所以它只在阅读就是目的的时候出现。
- 多数作品里彩色不到四成（见 [color-and-texture.md](color-and-texture.md)），层级不能全靠颜色，尺度的悬殊就承担了这个工作。
- 两个例外各有来由：V03 的章节卡是在逐条列举（图形、颜色、纹理、与现实结合），均匀的阶梯适合列举；V16 的字号是纵深造成的，大小在表示远近，不在表示主次。
- 第一眼落在哪里，由大小、反差、清晰度和颜色一起决定。「最大的不一定是第一位」那三例里，大的东西被压暗、虚化或做成和底同色，主次分别交给了清晰度（V05 0:55）、唯一的颜色（B01）和唯一的色块（B05）。

**适用与代价**

- 适用于以图形为主体、镜头短的片子和封面。
- 小字在低分辨率和低码率下会糊成一片。V27（720×720，约 1.2 Mbps）的小字基本无法辨认，V13、V17 的细线和小字也不可靠。小字的大小要按成片的分辨率和平台的码率来定，在交付的规格下看一遍。
- 有信息必须被读到时（歌词、活动的时间地点），给它中间档，并给它时间。不要为了「好看」把它压成小字。
- 「5—30 倍」是量出来的范围，不是配方。先定谁是唯一的大字，再让其余的明显小于它。

## 3. 小字的三种工作

**看到的**

| 工作 | 样子 | 例子 |
|---|---|---|
| 页眉页脚 | 固定在角落或边上的信息标签，跨镜头不动 | V10 每段的曲目信息、V11 四角的小词、V16 底边的信息栏、V18 左上角的片名和数字、V23 的四角字幕、V25 片尾的两列编号标签 |
| 纹理 | 读不出内容、只负责密度的小字 | V01 贯穿画面的小字线、V07 的虚构文字、V16 贴在地面上的字段名、V08 面板上的小标签 |
| 标注 | 用引线、方框、坐标把图形「标」成被测量的对象 | V08 的部件说明、V22 的坐标读数、V23 的打叉方框、V14 的白色细线方框、P01 的图解层、P18 的引线和节点图、P28 的取景器图形 |

**可能的原因**

- 页眉页脚给画面一种「这是一个系统的输出」的口吻，同时它是跨切点的锚点（见 [motion-and-transitions.md](motion-and-transitions.md) 第 3 节）。
- 纹理小字解决的是「大面积的空看起来没做完」的问题，又不引入新的主体。
- 标注把不同来历的东西放进同一张「图解」里。手绘角色放进三维场景或实拍时，素材里就是用细线方框和界面图形把两者标在一起的（V14 0:21—0:40、V21）。

**适用与代价**

- 每一处小字先定它是哪一种工作。页眉页脚要固定位置；纹理要成片、成行；标注要指着一样具体的东西。
- 纹理小字在 4K 高码率下是读得出来的（V01、V23、V34）。内容最好是与作品有关的真东西（曲名、参数、制作信息），不要放无意义的占位文字。
- 标注太多会让画面像界面截图。P21 是故意把整幅图做成一个系统窗口，那是一个完整的概念，不是装饰。

## 4. 同一个标题写两遍

**看到的**

- 平面作品里，同一个标题出现两次以上的：P02、P04、P22、P25、P30、P32、P33、P35、P37。P07 写了四遍（实心大字、手写体、空心竖排、边缘走马灯）；P19 有衬线大字、片假名方框、竖签和侧脊四处。
- 视频里：V00 0:22 的标题卡有超大的衬线字、贴四角的大号汉字和 6—10 像素的小字；V27 的标题卡把同一个词用三种字体各写了一遍。
- 大的那个常常被拉伸、裁切、转向或盖住；小的那个是端正的。

**可能的原因**

- 两个标题分了工：大的是图形，小的负责可读。有了小的兜底，大的才可以被破坏。
- 这也是第 1 节那个区分的直接应用：同一条信息，既做一份「只要被看到的」，也做一份「要被读的」。

**适用与代价**

- 适用于标题本身就是主视觉的封面和标题卡。
- 标题很长时，大的那一份可以只取一个词或几个字母。
- 写了两遍以后，小的那一份必须真的读得出来（位置稳定、反差足够、不被盖住），否则两份都成了图形。

## 5. 歌词站在哪里

**看到的**

| 位置 | 作品 | 做法 |
|---|---|---|
| 画面主体 | V07 | 斜排明朝体，汉字大假名小，背后有沿基线的拖痕 |
| | V08 | 三种排法按段落轮换：方格式、大字式、纸面式 |
| | V13（字体排印另有署名） | 每个词坐在一段五线谱上 |
| | V18 | 四种排法：字母泡、地面大字、方括号、窗内标签 |
| | V23（字体排印另有署名） | 两种字体混在一个词里，字母错位，像素化缺损 |
| | V27 | 压扁、镜像、叠压；1:24 是三层叠放 |
| | V34（平面设计另有署名） | 红底黑字的整屏歌词卡 |
| 画面边缘 | V14（歌词版式另有署名） | 竖排小字固定在右缘 |
| | V17 | 小号明朝体配上下点线，靠边，不压脸 |
| | V21（歌词设计另有署名） | 主歌用小号竖排印刷体；抒情段和副歌换成手写大字 |
| | V24 | 一行白色小字固定在底部居中，不参与构图 |

- 同一位作者的片子里两种位置都有（kkmfd：V07、V08 在主体，V17 在边缘）。
- 跟着唱的歌词，出现的间隔不均匀（逐帧量的）：V13 1:12 的词相隔 26、9、34、19、11 帧，平均约 20 帧，每个词用 3—8 帧落定；V17 0:27 的字相隔 7、17、14 帧。
- 歌词层常常跨切点不动，背后的插画换掉（V08、V13）。V13 0:40.4—0:42.2：歌词在黑底上逐个出现，排定后静止 14 帧，插画再从下面切进来，歌词不动。
- 歌词很少单独退场。逐帧看过的几处里，它被下一句原地替换（V07、V27），或者留在原地、换掉的是背景（V13）。V07 2:21 的歌词跟着整幅画面虚出，切点后对回焦，还是同一句（见 [motion-and-transitions.md](motion-and-transitions.md) 第 9 节）。

**可能的原因**

- 这是项目层面的决定，取决于画面里谁是主角。有一张完整的插画或一个三维场景要保护时，歌词退到边上；没有的时候，歌词自己就是画面。
- 歌词当主体时，它需要专门的字体设计。素材里这一层多半另有署名，说明它是一份独立的工作量。
- V21 在一条片子里换位置：主歌是小字，抒情段和副歌是大字。字的位置和大小在标记段落和情绪的强度。

**适用与代价**

- 歌词当主体：画面的每一段都要为字重新设计；字要足够大、停得足够久；插画只能退为背景。
- 歌词当字幕：不干扰画面，制作量小；但字和画面没有关系，容易像后加的。V17 用点线把字「系」在画面上，是一种折中。
- 听不懂这门语言的观众读不了歌词。面向这类观众时，歌词当图形用的比重可以更大。
- 不要转写或改写歌词。这里只讨论排法。

## 6. 字体的混用、变形和括号各自在做什么

这一节容易被当成元素清单来抄。每一项先写它在素材里做的事，再写什么时候它只是装饰。字的粗细、宽窄、字距、行距，以及放大、裁切、遮挡、重复这几种处理，第四轮逐帧量过、看过，展开写在 [typography.md](typography.md)。

| 做法 | 看到的 | 它在做的事（解读） | 只是装饰的时候 |
|---|---|---|---|
| 一个词或一句里混几种字体 | V23（细体无衬线加花饰衬线首字母）、V13（无衬线大写加衬线斜体上标）、V27 标题卡、P18、P07 | 在一个词内部制造主次，或者让一个词同时有两种口吻 | 混用没有对应到内容上的任何区别 |
| 汉字与假名分大小、分颜色 | V07、V08（群青汉字、黑色假名）、V34 | 汉字承担意义和形状，假名退成连接 | — |
| 标题字体跟着段落换 | V10 九段九种标题字体 | 字体是段落的身份 | 段落之间在别的方面没有区别 |
| 贴在带透视的地面上 | V16、V18 | 字成了空间的一部分，大小表示远近 | 画面里没有空间 |
| 沿路径或圆周排 | V05、V13、V18、V21 | 字跟着一个形状走，成为那个形状的边 | 没有那个形状 |
| 横向或纵向拉伸 | V01 的整屏汉字、V27 | 字被当成一块面积来填满画面 | 被拉伸的是需要读的字 |
| 镜像或倒置 | V00、V01、V02、V03、V10、V14、V18、V21、V24、V25、V27；P01、P06 | 压低可读性，把字变成图形；或者表示倒影、反面（V16 的光盘是从背面看的） | 这个字只出现这一次 |
| 拆成单个字母散开 | V05、V21、V23、P34 | 字母成了可以单独运动的元素 | 观众需要认出这个词 |
| 故障切片、局部像素化 | V23 的歌词、P22、P26、P28 的标题 | 字带上了数字劣化的质感，和画面的质感家族一致 | 画面其余部分是光学或手绘的质感 |
| 把标题转 90° 贴边 | P07、P26、P35、P37；V05 的竖排大字、V14 片尾 | 把边当成书脊，中间让给主体 | 这是唯一的一处标题 |
| 定制字标 | V08（保留辅助线的窄体字）、V34、P06、V16、P08、P37、P24 | 字标可以进入成片，成为母题 | — |
| 括号 | V02 的章节编号、V10 的曲目编号、V13 的上标词、V18 方括号里的歌词、V20 片名外的一对圆括号、V16 的方括号警示词、P04 | 把一个词标成「条目」或「旁注」，是目录和说明书的口吻 | 被括起来的东西不是条目也不是旁注 |

- Zeth 相关的 15 件平面作品没有固定的标题字体，用过粗体无衬线加手写体、宽体科技字、高对比衬线、哥特体、带故障切片的衬线字、贴纸式的定制字、手写体。不变的是结构：一个主色、标题至少写两遍、角落里成组的小标签、一层细线图形。这说明字体是跟着项目选的，结构才是可以带走的东西。

## 7. 窗口与画框

**看到的**

- 几乎每条片子都有「窗口」：在大面积的单色底上开一个有边界的画中画。
  - 黑底居中的窗口：V01、V05、V24 开场。
  - 浅底上的纸面或方窗：V07 的蓝天方窗、V17 的纸面、V20 的纸面窗、V26 的照片页。
  - 异形窗口：圆（V08、V13、V14）、圆角矩形（V00、V04、V17）、椭圆舷窗（V16）、切角或多边形（V08）、波浪边（V20、P33）、邮票齿边（V21）。
- 同一张图换一种框再出现：V07 的两张插画各换了五六种框；V08 同一张宇航员插画装进四种窗口。
- 平面作品里的画框：P07 的大圆角画框、P21 的系统窗口、P30 只包住几个角的切角框、P27 和 P29 的细边加错位投影。

**可能的原因**

- 窗口把一种画风的图（插画、照片、三维渲染）和图形层隔开。有了边界，两种画风就不必互相匹配，观众读到的是「设计里的一张图」。
- 换框是让有限的插画多出场几次、每次有新的样子。插画歌词类 MV 的插画张数有限，设计层在替它增殖。这是推断。
- 窗口的形状在带出内容的性格：舷窗、取景器、邮票、系统窗口各有指向。

**适用与代价**

- 有不同来历的图要并置时，窗口是最省事的办法。
- 窗口缩小了图的面积。插画是卖点时，要有几处让它满屏。V07 的副歌回到满屏。
- 窗口的形状不要从别的作品里借。先问这条片子的内容里有没有一个自然的「框」（屏幕、信封、取景器、窗）。

## 8. 画幅

**看到的**

- **片内变化**：V07 有 4:3 黑边、满屏、2.35:1 黑边、圆角小窗四种状态，主歌多用带边的画幅，副歌回到满屏。V24 有小窗、满屏、左右白边、上下黑边四种。V04、V16、V20、V23 也在段落间增减黑边。
- **整片固定的非常规画幅**：V02（约 21:9）、V14（约 2.35:1）、V27（正方形）、V34（宽银幕黑边）。V27 的正方形直接决定了三条竖向分区的版式。
- **同一设计做几种画幅**：P21、P22、P23、P28、P30 各有约 16:9 的横幅、窄横条（约 5:1，P28 约 10:1）和正方形三个版本。

| 项目 | 横幅 | 正方形 | 窄横条 |
|---|---|---|---|
| 标题与主体 | 标题偏向一侧，主体在另一侧或上方 | 主体在上、标题在下，或标题仍在一侧的中部 | 标题挪到最左；P28 去掉标题，只在中间放徽章 |
| 主体的裁切 | 完整 | 放大 | 只留脸或局部 |
| 界面小件 | 贴着画面边缘 | 贴着新的边缘重新摆 | 删减，只留少数几件 |
| 画框 | 完整 | 完整，角框形状有调整 | 只留一部分 |

- 跟着边走的：角标、小标签、画框、徽章。跟着主体走的：标题与人物的相对位置、前景的花瓣或光条。窄横条里放不下的东西直接删掉，而不是缩小。

**可能的原因**

- 片内换画幅是一种段落标记：收窄像是压住，放开像是释放。V07 把放开留给了副歌。
- 多画幅的三个版本说明，这些设计是按「附着关系」组织的：有的东西附着在边上，有的附着在主体上，有的可有可无。换画幅时，各自按自己的关系重新落位。
- 删而不缩，是因为小件缩小之后就失去了它的工作（读不出、看不清），留着只会添乱。

**适用与代价**

- 一开始就知道要出几种画幅时，设计阶段把每个元素标成「跟边」「跟主体」「可删」三类。之后适配只是按规则重排。
- 片内换画幅要省着用。它是一种很大的变化，适合留给段落（见 [rhythm-and-sound.md](rhythm-and-sound.md) 第 5 节）。
- 非常规画幅在平台上会被加黑边或裁切，先确认发布的地方怎么显示它。

## 9. 密度的三种策略

**看到的**（平面作品）

| 策略 | 例子 | 样子 |
|---|---|---|
| 把复杂度集中在一个团块，其余留白 | sorasignature 的 P10—P16 | 一个爆裂状的碎片团占画面的三分之一到一半，接着一两条水平色带；浅色中性底上只有很淡的纹理；两到三个颜色；文字很少 |
| 把整幅填满，用层次区分主次 | ariiol 的 P31、P32；kkmfd 的 P03、P04、P06；Zeth 的多数作品 | 画面没有空处，靠尺度、颜色和前后遮挡排出主次 |
| 大面积空底上只放一行字和几条线 | P18 | 字本身就是图 |

- 「重复当纹理」出现在第二种里：P07 的边缘走马灯、P24 的胶带、P29 叠三层的标签、P04 斜向排开的同形色块、P03 的小标签。

**可能的原因**

- 第一种在缩得很小时也读得出来（一个团块加一个词），适合横幅和缩略图。
- 第二种在大尺寸下耐看，细节多；缩小以后读到的是整体的质感和一个大字。
- 选哪一种，和有没有一张插画要突出、作品最常在多大的尺寸下被看到有关。这是推断。

**适用与代价**

- 填满的策略要求层级非常清楚，否则就是乱。素材里靠的是限色、尺度悬殊和一个明确的主体。
- 留白的策略要求那个团块足够有看头，而且位置经得起推敲。P12 右侧四成全空，P11 下方三成几乎全空。

## 10. 标题与图像的前后关系

**看到的**

- 标题夹在插画的层之间，而不是盖在插画上面：P01 前景的花瓣压住标题，标题压住裙摆；P19 人物的腿从标题前面跨过；P29 人物站在整幅标题大字的前面；P25 水滴遮住标题；P34 字母铺满全幅并与人物重叠。

**可能的原因**

- 标题有了前后关系，就进入了画面的空间，成为图像的一部分，而不是贴在上面的标签。
- 被遮住的标题可读性下降，这正是需要第二份小标题的地方（第 4 节）。

**适用与代价**

- 需要插画是分层的，或者能抠出前景。
- 遮挡的位置要选在不影响认字的地方（笔画的末端、字与字之间），或者干脆接受它不可读。

## 11. 界面与图解小件

**看到的**

- 刻度、编号、引线、警示图标、勾选框、程序窗口、取景器角标、条码标签。34 张平面作品里至少 25 张有。
- 视频里：V03、V05、V11、V14、V16、V25 把软件界面、表达式文字、鼠标指针、弹窗放进画面（见 [structure-and-motif.md](structure-and-motif.md) 第 5 节）。
- 第三轮的图片里又看到几种：
  - 系统报错弹窗，十几个散在画面中下部（B02）。
  - 「:(」图标和两行表达式文字（B04）。
  - 线段端点上的小方框，像软件里的控制点；带对角线的白色方框，像图片占位符（B05、B07，即 V05 0:47、0:50）。
  - 软件字符面板的截图和一段聊天界面的截图（B08）。
  - 代码编辑器的截图，装在一个白色的圆里；一段带注释的文件清单（B13、B12，即 V00 0:27、0:28）。
- 透明底纹样的棋盘格也是这一类符号，单独写在 [color-and-texture.md](color-and-texture.md) 第 9 节。
- 左右两缘在同一高度成对放的标记：B01 的括号字、B10 的圆环组。

**可能的原因**

- 这些小件借用了仪器、软件、包装上「功能性图形」的样子，给画面一种被测量、被操作的口吻。
- 它们尺寸小、数量可调，是调节密度最方便的材料。
- 成对贴边的标记给满屏的内容一条看得见的中线，作用接近 V00 的刻度尺和 V05 0:50 的水平轴线。

**适用与代价**

- 小件要有出处。和作品的内容或制作有关的（曲速、曲目编号、制作软件的界面）站得住；随手拿来的通用图标会让不同作品看起来一样。
- 它们属于第 3 节的三种工作之一时才留下。
- 界面截图里的小字在平台成片上基本读不出来。B13 白色圆里的代码在图片上逐行可读，在成片的同一帧上是糊的；B12 的文件清单在成片上连橙色都掉了。它们在成片里起的是纹理的作用。想让内容被读到，要放大、给时间，或者另外发静帧。

## 12. 在自己的稿子上怎么查

| 想确认的事 | 做法 |
|---|---|
| 字号有几档，大字有几处 | `typesize.py <编号> <帧号>`：各行字高占画面高度的百分比。只在底色干净的画面上可信 |
| 小字在成片里还在不在 | 按交付的分辨率和码率编码一遍，逐帧看最小的那几行 |
| 要被读的字有没有读的时间 | 用步长为 1 的条带数它完整停留的帧数。素材里一个要读的词或一句歌词停 22 帧到 40 帧以上，占满画面的大词停 5—10 帧（[motion-and-transitions.md](motion-and-transitions.md) 第 9 节） |
| 第一眼落在设想的地方吗 | 把画面缩到很小看一眼，再只看 0.1—0.3 秒。大的东西如果被压暗、虚化或与底同色，第一位是别的东西 |
| 层级是否清楚 | 把画面缩到很小，或者转成黑白二值，看第一眼落在哪里 |
| 多画幅适配是否成立 | 把每个元素标成跟边、跟主体、可删，按规则摆出另一个画幅，看还缺什么 |
